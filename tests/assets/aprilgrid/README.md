# Kalibr AprilGrid fixture

`kalibr_aprilgrid_6x6.png` is used by `tests/test_kalibr_aprilgrid_fixture.py` to check
whether this project's AprilGrid detector (`calibration/detector.py::detect_aprilgrid`)
can actually detect a Kalibr-style AprilGrid target, as opposed to only the
OpenCV-rendered synthetic tags the rest of the test suite uses.

## Provenance (read before trusting this as "real Kalibr output")

This image was **not** produced by running Kalibr
(<https://github.com/ethz-asl/kalibr>). This environment has neither Kalibr installed
nor a camera to photograph a printed target with. It was generated by
`scripts/generate_kalibr_aprilgrid_fixture.py`, which re-implements Kalibr's published
AprilGrid target convention as closely as possible without running Kalibr itself:

| Property | Value | Matches Kalibr because |
|---|---|---|
| Tag family | `tag36h11` (OpenCV `DICT_APRILTAG_36h11`) | Kalibr's AprilGrid default family. 36h11 codewords are a fixed standard, so the encoded tag content is identical regardless of which tool rendered it. |
| Grid size | 6 columns x 6 rows (36 tags) | Arbitrary but typical size, matches the filename. |
| ID layout | row-major, tag 0 at top-left, increasing left-to-right then top-to-bottom | Same convention this project already documents in `build_aprilgrid_dictionary()`'s docstring and Kalibr's own AprilGrid layout. |
| `tagSize` | 0.05 m | Arbitrary physical size. |
| `tagSpacing` | 0.3 (fraction of `tagSize`) | Kalibr's common default; same formula this project uses in `export/kalibr.py::build_kalibr_aprilgrid_target()` (`tagSpacing = (square_size - marker_size) / marker_size`). |
| Rendering | White page, black-bordered tag images (`cv2.aruco.generateImageMarker`) placed on a grid | Same black-on-white layout as a printed Kalibr PDF target. |

What is **not** faithfully reproduced: Kalibr generates its target as a PDF via
matplotlib/LaTeX, meant to be printed and then photographed with a real camera. That
real pipeline introduces print DPI quantization, sub-pixel antialiasing, lens
distortion, and lighting variation that this synthetic PNG does not have. So this
fixture proves "OpenCV's AprilTag36h11 detector can read the tag content and row-major
ID layout Kalibr targets use" — it does not by itself prove full compatibility with an
actual printed-and-photographed Kalibr target.

## Swapping in a real Kalibr-generated image later

If you have Kalibr installed, or a real photo of a printed Kalibr AprilGrid target,
replace `kalibr_aprilgrid_6x6.png` with it **keeping the same filename**. No test code
needs to change — `tests/test_kalibr_aprilgrid_fixture.py` reads the file by path, and
its ID/geometry assertions are derived from a `PatternConfig` you'd update to match
your real target's `squares_x`/`squares_y`/`square_size`/`marker_size`
(see `_kalibr_pattern_config()` in that test file).

## Regenerating

```
python scripts/generate_kalibr_aprilgrid_fixture.py
```
