# 실제 Calibration 품질 원인 진단

2026-11-03. 기존 ROSbag E2E 결과를 재사용했다. **주요 원인은 서로 다른 fit의 지표를 비교한 점, 전체 35장 fit의 초기화·수렴 민감성, Fisheye의 부적합 초기값과 일부 부분 보드 프레임이다.** 높은 Coverage만으로 좋은 K/D나 정확도가 보장되지는 않는다. 제품 알고리즘·추천 가중치·품질 임계값은 변경하지 않았고 신규 파라미터를 승인/Export/차량 적용/게시하지 않았다.

## 1. 10.516px와 1.592px는 무엇이 다른가

|항목|최종 Fit RMS 10.515849px|Hold-out Test RMS 1.591968px|
|---|---|---|
|이미지|기존 자동 선정 35장 전체|별도 28장 Train으로 학습 후 7장 Test|
|K/D|Rational 전체 fit 결과, YAML에 Export됨|Train 28장만으로 학습한 별도 K/D|
|계산|모든 코너 오차 제곱합 / 코너 수의 제곱근|각 Test 프레임 RMS 제곱의 평균 후 제곱근|
|Test 처리|기존 최종 전체-fit에는 Hold-out 7장도 포함됨|Test에서 K/D 고정, 각 프레임의 pose만 추정|

기존 CLI/`run_all_models`는 전체 fit을 만들고 `validate_all_models`는 동일 seed=42의 Train/Test 분할로 따로 학습한다. 일반적인 전체 재학습 결과와 Hold-out 검증을 구분해야 한다. **1.592px는 Export된 전체-fit K/D에 대한 독립 Test 검증 수치가 아니다.** 이번에는 이 기존 35장 fit을 재학습하지 않고 저장된 값만 읽었다. 새 fit에는 고정 Test 7장 픽셀을 전부 제외했다.

동일 7장에 대한 point-weighted Test RMS는 1.680051px다. 평균 방식 차이도 있지만 10.516 vs 1.592의 큰 차이를 설명하지는 못한다.

## 2. 전체-fit이 나쁜 해에 머물렀다는 근거

Train-only K/D, 학습 때 얻은 28개 pose, 기존 Test pose-only 평가를 결합하면 원래 35장의 동일 1,262코너에 **1.545861px**의 실현 가능한 잔차를 얻는다. Test로 K/D를 학습하지 않았다. 이는 10.516px가 이 데이터에서 피할 수 없는 최적 잔차가 아님을 보여 준다. 전체-fit의 초기화/비선형 최적화/종료 조건에 민감한 비최적 해라는 해석을 강하게 뒷받침한다. 어떤 내부 반복에서 잘못된 basin에 들어갔는지까지 확정한 것은 아니며, 낮은 잔차의 K/D가 물리적 정답이라는 증명도 아니다.

기존 전체-fit K/D를 같은 7장에 고정하고 pose만 재추정하면 RMS=9.501859px다. 이 값은 전체-fit에 그 7장이 이미 포함됐으므로 독립 Hold-out 성능으로 보고하지 않는다. 두 K/D의 차이가 실제 투영 결과에도 영향을 준다는 사후 진단이다.

주의: Train-only K/D로 Train pose를 처음부터 solvePnP로 다시 추정하면, 부분 보드 7코너 프레임 000005에서 잘못된 pose로 RMS 약 2659.96px가 나온다. 학습으로 공동 최적화한 그 프레임 pose의 RMS는 0.940810px다. **새 pose solver의 실패를 K/D의 실제 학습 오차로 혼동하지 않았다.** 위 1.546px 계산에는 원래의 학습 pose를 사용했다.

## 4. Fisheye 예외와 입력 조건

기존 전체 35장 실행의 저장 예외는 OpenCV `InitExtrinsics`, `fabs(norm_u1)>0` assertion이다. Hold-out 28장 경로를 이번에 실제 native 호출 단위로 추적하니 `CalibrateExtrinsics`, `CALIB_CHECK_COND`, `input array 0` 조건수 오류가 반복됐다. OpenCV 공식 5.0.0 소스에서도 초기화는 정규화 좌표의 homography를 분해하고 해당 열의 norm을 확인하며, extrinsic Jacobian 조건수 검사가 별도로 수행된다. 실제 wheel의 파일 줄 번호와 공개 태그의 줄 번호는 다르므로 함수/검사 논리를 대조했다. [OpenCV 공식 소스](https://raw.githubusercontent.com/opencv/opencv/5.0.0/modules/calib/src/fisheye.cpp)

입력 dtype=float64, shape=(1,N,2)/(1,N,3), 좌표 finite를 확인했다. 전체 planar object 좌표가 rank 2인 것은 정상이며 3D rank 3 부족을 오류로 취급하지 않았다. 이전 OpenCV shape/flag 호환성 문제가 다시 발생한 것이 아니다.

### 동일 Train-only 28장에서 초기값만 진단 비교

|기존 함수 initial_guess 옵션|결과|유지 Train|Train RMS(px)|고정 Test RMS(px)|
|---|---|---:|---:|---:|
|pinhole_train28|실패|최대 재시도 소진|N/A|N/A|
|default_no_guess|수치 계산 성공|27|1.516407|1.613604|
|rational_train28|수치 계산 성공|27|1.516407|1.613604|

기존 Pinhole Train 초기값 fx=472.376/fy=470.787은 zero-distortion 모델의 좋지 않은 fit(RMS 19.356px)이다. 이를 Fisheye의 D=0 초기값으로 가져가면 입력 정규화 반경 최대 4.407, 코너 81.96%가 반경 π/2보다 크고, native fisheye undistort 정규화 결과 절대값은 약 4.24e16까지 커진다. Train-only Rational 초기값 fx≈1914.715/fy≈1923.128에서는 최대 반경 1.061, 큰 정규화 값이 나타나지 않았다. 따라서 “수치 계산 success인 Pinhole K라면 항상 좋은 Fisheye seed”라는 가정은 이 자료에서 성립하지 않는다.

Pinhole seed는 native 25회 모두 실패했고, 28→4프레임까지 줄어드는 동안 매번 index 0 오류를 보였다. 이는 25장의 실제 불량이 확인됐다는 의미가 아니다. 반대로 초기값 없음/Rational seed는 각각 native 2회(28장 실패→문제 1장 제외한 27장 성공)로 끝났다.

두 성공 경로에서 제외된 것은 `capture_000005_e8c1fca679b94372b393b8913ffcbff8`: 코너 7개, 이미지상 폭×높이 약 1964×366px, object XY singular values 0.48025/0.08065다. 가까워 잘린 보드의 가늘고 치우친 2D 지지 영역이다. 정확히 일직선은 아니지만 초기 extrinsic 추정에 불리하고, 기존 일반 solvePnP의 별도 pose 재추정에서도 불안정했다. 원본을 시각 확인했다.

이 비교는 기존 공개 함수가 받는 초기값 옵션을 사용한 진단이다. 기본 Fisheye 경로/재시도/기준을 수정하지 않았다. 전체 35장 내부 반복을 새로 돌려 추적하지 않았으므로 전체-fit assertion의 모든 세부 원인을 Hold-out seed 하나로 단정하지 않는다. 성공 진단도 새로운 운영 모델로 승인하거나 자동 추천하지 않았다.

## 5. 전체 90장과 다른 선정 집합

기존 Test 7장을 픽셀 SHA-256으로 고정하고, 새 fit에는 이 7장과 동일 픽셀을 넣지 않았다. 따라서 90장 전체를 그대로 재학습하지 않고 **90−Test 7=83장**을 Train 후보로 사용했다. 이미지 ID가 서로 다른 두 추출본 사이에서도 해시로 교집합을 검사했다.

선정은 기존 품질·기하 선정 함수를 그대로 사용했다. Test 오차를 보고 후보/가중치/임계값을 바꾸지 않았다. 83장 전체, 그 안에서 선정한 35장, Test와 동일 scene cluster를 제외한 47장을 사전 계획으로 고정했다. Test를 기준으로 파라미터를 최적화하지 않았지만 동일 7장으로 여러 진단을 보았으므로 이후 최종 확인에는 새로운 독립 Test가 필요하다.

|Train 구성|장수|Full Coverage|Observable|Brown Train/Test RMS|Rational Train/Test RMS|
|---|---:|---:|---:|---|---|
|baseline_train28|28|68.75%|84.78%|2.584/2.718px|1.501/1.592px|

Train-only Rational fx는 위 네 집합에서 약 1903.08~1926.87px, fy는 1913.55~1945.32px로 모였고, 기존 전체-fit fx=5731.97/fy=5447.52와 큰 차이가 있다. 이는 전체-fit 해의 민감성을 다시 뒷받침하지만 올바른 물리 정답을 확정하는 것은 아니다.

원래 Train 28장 중 17장이 Test와 같은 기존 유사 scene cluster에 속한다. 동일 픽셀/동일 ID의 Test 학습 누수는 없지만 연속 녹화의 유사 자세 상관 때문에 Test의 독립성이 약할 수 있다. cluster는 pHash·기하 조건의 보수적인 전이적 묶음이지 실제 동일 장면의 정답 라벨은 아니다. 그룹 분리 Train 47장에서는 Rational Test가 1.853px, Brown Test가 15.001px로 달라졌다. 특정 Test 숫자 하나로 안정성을 판단해서는 안 된다.

전체 90장으로 후보가 늘거나 선정 Coverage가 75%로 높아져도 동일 Test가 자동으로 좋아지지는 않았다. 가장 낮은 Test 숫자를 얻도록 선정 로직을 재튜닝하거나 임계값을 내리는 변경은 하지 않았다.

## 6. Coverage·거리·Tilt 지표의 한계

Observable Coverage는 가려진 보닛을 제외한 공간 분포 지표이며 렌즈의 비선형 수렴이나 점 배치의 조건수를 보장하지 않는다. 이번 자동 종료 35장은 Full 68.75%/Observable 77.03%로 공간 기준을 통과했지만 전체-fit은 나빴다. 이를 Coverage 기준 오류 또는 Threshold 완화 사유로 해석하지 않았다.

기존 거리 다양성은 보드 면적 비율의 상대 퍼짐을 0~1로 포화시킨 대리값이고, Tilt 다양성은 minAreaRect 2D 각도 퍼짐이다. 실제 3D yaw/pitch 다양성과 동일하지 않다. 매우 가까운 부분 보드나 직사각형 각도 표현의 약 90도 전환도 점수를 높일 수 있다. 네 비교 집합 모두 거리/Tilt score=1.0이지만 결과는 달랐다.

Train-only Rational pose에서 추정한 보드 normal Tilt는 약 5.25~53.38도(중앙값 21.64도), z는 약 0.140~1.649m(중앙값 1.022m)다. 확인된 Square 100mm/가정된 평면과 추정 K에 의존하는 진단값으로, 독립 측정 거리나 자세 정확도는 아니다. 거리·기울기·화면 위치가 서로 결합된 분포, 부분 보드의 2D 지지 영역, 초점/흔들림을 함께 살펴야 한다.

## 7. 보드 설정 확인

Train 이미지 7장을 표본으로, 각 Marker 주변의 검출된 4개 checker 교차점을 단위 정사각형으로 사영 정규화했다. 66개 관측의 Marker/Square 비율 중앙값=0.74240, P10~P90=0.73264~0.74904였다. 가정 0.75와 크게 동떨어진 패턴이라는 증거는 없지만 인쇄 Marker 75mm를 확인한 것은 아니다. 국소 왜곡·평면성·기존 가정으로 보간된 코너를 사용한 순환성 때문에 물리 치수 측정으로 대체할 수 없다.

같은 7개 Train 이미지에서 Marker 설정 70/75/80mm로 검출만 비교했다. 공통 코너 위치 변화는 최대 0.04064px였고 표본의 검출 코너 수는 동일했다. 수 px~수십 px의 잔차를 Marker 길이 오차에 따른 직접 코너 위치 이동만으로 설명하기는 어렵다. 다만 비선형 최적화 민감도를 통한 영향까지 부정하지 않으며 75mm는 계속 미확인 가정으로 유지한다. 10×7·DICT_5X5_100·Square 100mm는 사용자 확인값으로 유지했다.

## 8. 근거에 따른 우선순위

1. **서로 다른 fit의 품질을 분리해 검토한다.** Export된 전체-fit K/D와 실제 Hold-out을 산출한 Train-only K/D에 각각 식별자/지표를 연결하고, 현재 높은 전체-fit 오차·POOR/REJECT 결과는 운영 승인하지 않는다. 새 모델을 Test까지 재학습한 뒤 같은 Test 점수를 성능 보증으로 붙이지 않는다.
2. **Train-only 초기화·수렴 안정성부터 확인한다.** 기존 Fisheye 옵션의 cold/Rational seed 결과를 독립 촬영분에서 재검증하고, 전체-fit의 다른 초기 해/수렴 원인도 별도 승인된 개발 범위에서 검토한다. 현재의 최소 잔차만 보고 기본 알고리즘이나 최종 모델을 바꾸지 않는다. Pinhole success를 좋은 seed로 간주하는 정책은 향후 개선 후보지만 이번 작업에서 수정하지 않았다.
3. **장수·Coverage 외의 기하 지지 영역을 선정 근거로 검토한다.** 7코너로 가늘게 잘린 초근접 프레임처럼 pose가 불안정한 자료를 식별하고, 충분한 행·열의 checker 교차점이 보이며 선명한 중거리 보드, 좌우 관측 가능한 가장자리, 여러 out-of-plane 자세를 추가한다. 하단 보닛은 촬영 요구에서 제외한다. 새로운 수치 cutoff는 이 분석만으로 정하지 않는다.
4. **독립 촬영 구간으로 검증한다.** 연속 인접 프레임 무작위 분할만으로 확신하지 말고 촬영 자세/시퀀스 그룹을 분리한 Train/검증과 새로운 최종 Test를 확보한다. 기존 90장을 더 사용하는 것만으로 Test 개선은 보장되지 않았다.
5. **물리 설정을 확인한다.** Marker black border 외곽 한 변, Square, 보드 평면성/강성, 실제 카메라 모델·렌즈·초점/해상도 모드를 실측·확인한다. 영상 기반 0.742 비율을 74.2mm 정답으로 자동 입력하지 않는다. 앞유리 영향, 보드 휨, 초점/흔들림을 각각 분리하는 통제 실험은 이번에 수행하지 않았으므로 남은 잔차의 원인으로 확정하지 않는다. 실제 장착 상태와 같은 조건의 독립 검증이 필요하다.

## 9. 변경·재현성·테스트

명확한 제품 구현 버그를 확정하지 못했으므로 **제품 소스 수정 없음**. 관측된 것은 전체-fit과 Hold-out의 다른 정의, 초기값/수렴 민감성과 기존 제한된 데이터의 불안정이다. 기본 알고리즘을 바꾸는 수정이나 Test에 맞춘 보정은 수행하지 않았다. 진단 스크립트는 `.verification/quality-diagnosis/`에만 추가했고 보고서는 이 문서다.

실제 증거 assertion 테스트 **8 PASS / 0 FAIL / 0 SKIP / 0 XFAIL**. 기존 CLI Hold-out 정확 재현, Test 해시 분리, 저장 Fit RMS 복원, 오차 집중, Test K/D 학습 없는 낮은 실현 가능 잔차, Fisheye 초기값 민감도, Marker 미확인 상태, 기존 소스 및 저장 이미지 보존을 검증했다. 제품 소스 수정이 없어 전체 P1~P4 회귀를 불필요하게 다시 수행하지 않았다. 이 8 PASS는 Calibration 품질 PASS가 아니다.

새 진단 fit은 Brown/Rational 비교 8회 + baseline Pinhole 1회, Fisheye seed 3개 구성이다. Fisheye 내부 재시도는 원래 알고리즘 그대로다. 완료된 fit JSON은 재사용하고 로그를 분리했다. 원본 ROSbag을 재추출하지 않았으며 기존 이미지 90장과 신규 저장 35장 SHA-256이 기존 Manifest와 일치한다. 기존 코드 SHA-256도 동일하다. 커밋·Push·배포·차량 적용·자동 승인은 하지 않았다.

주요 증거: `frozen-plan.json`, `fit-*.json`, `experiments.log`, `fisheye-native-calls.jsonl`, `fisheye-*.json`, `fisheye-input-geometry.json`, `marker-ratio-evidence.json`, `sensitivity.json`, `summary.json`, `tests.xml`. 기존 E2E의 분할/CLI 검증과 결과는 `.verification/e2e-mask/` 및 [E2E 보고서](ROSBAG_OCCLUSION_E2E_REPORT.md)에 보존되어 있다.
